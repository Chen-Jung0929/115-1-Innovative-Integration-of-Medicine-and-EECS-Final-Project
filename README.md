# 即時關節動作分析系統

國立臺灣大學 115-1 醫學電資創意整合專題 · Real-Time Joint Motion Analysis System

這是一套讓團隊以瀏覽器觀察人體動作、檢查膝部影像平面角度的學術概念驗證（PoC）。
**不提供醫療診斷或治療建議，模型估計值不是經驗證的臨床角度。**

## 安裝與啟動

先安裝 Node.js（本次使用 24.22.1，見 `.nvmrc`）。本版目前在 `feature/controlled-single-recovery`，尚未合併 main；
請取得這個分支的檔案。已有 Git checkout 的組員可在專案目錄執行：

```sh
git fetch origin
git switch feature/controlled-single-recovery
```

接著安裝並啟動：

```sh
npm ci
npm run dev
```

依終端機提示在本機瀏覽器開啟開發頁面。建議新版 Chrome／Edge，須支援
`requestVideoFrameCallback`。雲端 npm 快取若無法寫入，改用：

```sh
npm ci --cache /workspace/.cache/npm
```

安裝會自動把已鎖定的 `@mediapipe/tasks-vision` 套件內 WASM 複製到
`public/mediapipe/wasm/`。**不使用外部 WASM CDN**，勿混用其他版本。
正式建置使用 `npm run build`，`npm run preview` 可在本機檢查建置結果。
## 首次使用姿態辨識

選取影片後按「開始分析」，或切到「即時鏡頭」按「開啟鏡頭」。看到「正在準備姿態辨識功能」時稍候即可。首次使用時，若本站沒有提供模型，瀏覽器會自動向 Google 取得固定版本的 Pose Landmarker Lite。影片、鏡頭影像與分析結果都在本機處理。

若看到「模型載入失敗，請確認網路後重試」，恢復網路後按重試即可。需使用指定模型的研究者，可在「上傳影片 → 進階設定：辨識模型」選取本機 .task。兩種輸入共用此選擇；研究 JSON 保存實際來源、套件版本與 SHA-256。詳見[模型與資源說明](docs/MODEL_SETUP.md)及[本次驗證紀錄](docs/updates/iteration-19.md)。

手機與直向平板將角度讀數排在影像下方；桌面使用較寬的影片與讀數雙欄，下方曲線隨頁寬展開。可查看[五種螢幕尺寸的影片與鏡頭截圖](docs/updates/iteration-20.md)。

## 一般組員操作：單人影片分析

1. 準備單人、固定鏡頭、完整人體入鏡的側面 Squat MP4。避免遮蔽與畫面外動作；「單姿態」模型不會替我們確認現場只有一人。
2. 選取 MP4；畫面會顯示檔名、長度及尺寸。
3. 按「開始分析」。不需 ROI；模型收到完整原圖，每秒 10 次目標取樣（ADR-081；網址加 `?hz=5` 可重跑舊的 5 次設定以便比較）。進度會更新，也可取消。
4. 完成後播放、暫停或使用取樣滑桿，檢查骨架、左右膝 2D 內角及下方時間曲線；播放不會重新執行模型。
5. 無效量測顯示 **N/A**，曲線留斷點，不以 0°、前一角度或插值補上。暫時缺點與恢復確認中的樣本均保留無效。
6. 按「下載 CSV」匯出角度，或「下載研究 JSON」保存原始 landmarks、候選、QC、時戳與版本。關閉網頁前先下載，沒有自動上傳或保存。
7. 按「重新分析」重跑同一影片；變更設定後舊結果會標示過期並保留舊 JSON，不會悄悄混入新角度。

定義：髖–膝–踝在膝點的影像平面內角，先按原始影片寬高還原像素；暫定屈曲 proxy 是 180° 減內角。
左右為人體解剖側，不是畫面左右。角度受視角、遮蔽、模型錯點影響，並非經驗證的臨床屈曲角。
綠色骨架與自動 QC 通過也不等於人工確認或角度真值，請同時看原片與量測有效狀態。

### 深蹲姿勢指標（暫定，待物理治療師確認）

膝角下方另外顯示三項深蹲常看的指標，曲線區可用「曲線指標」切換，CSV 也會多出對應列：

| 指標 | 依據 | 怎麼算（2D 影像平面） | 0 代表 | 適合拍攝角度 | CSV `joint` |
|---|---|---|---|---|---|
| 髖角（左右） | 自訂 | 肩–髖–膝在髖點的內角；暫定髖屈曲 proxy = 180° − 內角 | 內角 180° ≈ 站直 | 側面 | `hip` |
| 上身（軀幹）前傾 | 自訂 | 兩髖中點→兩肩中點連線與畫面垂直線的夾角 | 上身直立 | 側面 | `trunk_lean` |
| 膝蓋對腳尖線（膝蓋內夾，dynamic knee valgus） | 講義 p.11 | 膝蓋離「過腳尖的鉛垂線」的水平距離，以骨盆寬為單位；+ = 膝在內側 | 膝蓋在腳尖線上 | 正面 | `knee_toe_offset` |

- 依據欄：「講義 p.X」= 團隊物理治療講義 Movement analysis 該頁的觀察重點（講義沒有數字門檻）；「自訂」= 講義沒有，依使用者需求加入。講義 p.11 的標準是膝蓋在腳尖或第二趾鉛垂線上或微外側，且左右對稱；MediaPipe 沒有第二趾點，以腳尖點（foot index）代替。
- 從正面拍時，上身前傾這個角度量到的其實是講義 p.9 的「軀幹側彎」（軀幹應平行鉛垂線）；從側面拍才是前傾。
- 點位不可靠（缺點、低信心、出畫面、退化幾何）或人物身分未通過時顯示 **N/A**，不補值。髖角與膝蓋對腳尖線跟隨同側膝的逐側 QC；人工標成非目標時全部無效。
- 以「畫面垂直」當鉛垂線，手機需擺正；側面拍攝時兩髖重疊，膝蓋對腳尖線會判為無效。
- 目前只顯示數值，**沒有提醒門檻**；定義與是否需要門檻待物理治療師確認。舊版（schema 9 以前）的研究 JSON 沒有這些指標，需重新分析。

### 醫學組正面檢查（點位、基準線、提示；暫定，待醫學組確認）

勾選「醫學組正面檢查」（預設開啟）後，影片上會多畫一層，並在左上角顯示提示：

- **點位**（講義 p.5）：眉心（兩眼中點）、鼻子、耳、肩（≈肩峰）、兩肩中點（≈胸骨上緣）、兩髖（≈ASIS）、兩髖中點（≈恥骨聯合）、膝（≈髕骨中心）、腳尖（≈第二趾）、腳跟。MediaPipe 沒有下巴、脊椎、ASIS 等點，以最接近的點代替。
- **基準線**：紅色直線。開始時請個案**站直、不動約 1 秒**（兩膝彎曲都 < 20°、兩腳跟位置穩定），系統用這段時間的**軀幹中線**（兩肩中點與兩髖中點）定出位置並**固定**；之後身體怎麼動線都不動，只有腳跟明顯移動（超過約 0.35 個骨盆寬、持續 0.6 秒）才重新校正。可在「基準線位置」切換成講義 p.5 的原始定義「通過兩腳跟中點的垂直線」。
  - 為什麼預設用軀幹：個案兩腳常站得不完全對稱、鏡頭也可能沒有正對，兩腳跟中點就不會在身體正中間，導致「動作正確也一直提示」。以「個案自己站直的樣子」當標準，可以抵消站姿與鏡頭的影響。
- **相對於站直時**：頭偏、重心偏移、兩肩傾斜、骨盆傾斜、軀幹側傾，都是和**站直校正那 1 秒**比較的變化量（手機稍微沒擺正、個案本來就有點高低肩，不會被當成錯誤）。膝對腳尖線仍看絕對位置（講義 p.11）。
- **檢查線**（線旁有文字標籤、左下角有圖例）：黃線為目前的兩肩線、骨盆線；白色虛線是**站直時**的肩線／骨盆線，兩條線張開代表變歪；藍色虛線為軀幹；綠色虛線為過腳尖的鉛垂線；超過門檻時變紅。此模式下原本的綠色骨架會淡化。
- **提示**（一次最多 2 則、持續約 0.2 秒以上才出現，避免閃爍）：

| 檢查 | 講義 | 看什麼 | 提示範例 | 暫定門檻 |
|---|---|---|---|---|
| 頭在中線 | p.7 | 頭（眉心）離基準線多遠（相對站直時） | 頭偏離中線（往右） | > 0.35 個骨盆寬 |
| 兩肩水平 | p.8 | 兩肩連線的傾斜（相對站直時） | 右肩比較低（兩肩不平） | > 5° |
| 軀幹 | p.9 | 軀幹側傾角；骨盆中點偏離基準線（相對站直時） | 上身往左傾／重心往左偏 | > 8°／> 0.25 個骨盆寬 |
| 骨盆水平 | p.10 | 兩髖連線的傾斜（相對站直時） | 骨盆往右傾（兩側不水平） | > 5° |
| 膝對腳尖 | p.11 | 膝蓋在腳尖鉛垂線內側多少（蹲下超過 30° 才判斷） | 左膝往內，沒有對準腳尖 | > 0.45 個骨盆寬 |

- **說出原因**：講義的錯誤示範常寫「頭不在中間，因為軀幹往左傾」。頭偏或肩不平與軀幹側傾同方向時，合併成一則，例如「上身往左傾（頭偏離中線、兩肩不平）」。
- 左右指**個案本身**的左右，影片鏡像或面向／背對鏡頭都不影響。
- 只適用**正面拍攝**；身體轉向鏡頭超過約 40°（肩寬／軀幹長 < 0.55）時提示框顯示「請正面拍攝」，不判斷也不提示。全部是 2D 影像平面幾何，以畫面垂直當鉛垂線（手機需擺正）；門檻是暫定值，**待醫學組確認**。人物身分未通過或人工標成非目標時不畫線也不提示。
- 這些數值是播放時即時計算的，不寫進研究 JSON／CSV，所以之後改門檻不會改到既有分析結果。

#### 側面檢查（講義 p.12，暫定）

系統會**自動判斷拍攝角度**（肩寬／軀幹長 ≥ 0.55 為正面、≤ 0.3 為側面、中間為斜拍）。側面時改畫側面的線，正面的基準線、肩線、骨盆線不畫；斜拍時兩種都不判斷，提示框請使用者正面或正側面拍攝。側面只看靠鏡頭那一側的腿。

| 檢查 | 看什麼 | 線 | 提示 | 暫定門檻 |
|---|---|---|---|---|
| 膝蓋前移 | 膝蓋超過「過腳尖的鉛垂線」多少，以小腿長為單位（蹲下超過 30° 才判斷） | 綠色虛線＝腳尖線；白線＝小腿 | 膝蓋超過腳尖太多 | > 60% 小腿長 |
| 上身前傾 | 髖→肩連線與畫面垂直的夾角 | 藍線＝軀幹；白色虛線＝垂直參考 | 上身前傾太多 | > 45° |

講義 p.12 寫的是「小幅屈膝時膝蓋前移約 3–8 cm」與「軀幹維持平滑曲線」。影片沒有公分尺度，也沒有脊椎點，所以改用小腿長比例與髖→肩直線代替，門檻**待醫學組確認**；深蹲蹲很低時膝蓋超過腳尖本來就常見，門檻不能直接套用講義的小幅屈膝數字。

### 遇到暫時異常

- 膝／踝缺失、低信心、退化幾何或腿段跳變：只拒絕受影響側；可信觀測需連續通過確認，之後才恢復該側角度。
- 首筆無姿態／軀幹失信：等待可靠初始化，不把整段永久設為無效。
- 已追蹤後短暫完全缺失：須在既有 650ms 安全窗口內完成軀幹確認，再完成各側關節確認；等待仍為 N/A。
- 若提示人物一致性無法確認：請檢查影片是否符合單人、固定鏡頭、完整入鏡條件，重新分析或換合適片段。系統不會自動解除真正的身分疑慮。

需要查看原始失敗原因或逐樣本標註時，展開「研究診斷與人工檢查」。人工 Wrong／Mixed／Uncertain 會使最終角度無效，原自動決策另存。
輸出含人體特徵與來源檔名，請存於受限空間，不要提交 Public GitHub。

## 一般組員操作：即時鏡頭（V1 初版）

1. 開啟網站，按上方「即時鏡頭」。
2. 選鏡頭方向：筆電或自拍選「前鏡頭」；手機或平板架在旁邊拍選「後鏡頭」。開啟後若裝置有兩個以上鏡頭（手機、平板都可以），會出現「切換到前／後鏡頭」按鈕，可直接切換（前一段會先保存）。「畫面左右鏡像」只影響顯示，左右膝仍以身體為準。
3. 按「開啟鏡頭」，瀏覽器詢問權限時選允許。之後不用再碰裝置：走到畫面中、頭到腳入鏡、**站好不動約 1.5 秒就自動開始量測**。
4. 量測中會即時畫出骨架與左右膝角度，下方是最近 15 秒曲線（每秒約 10 次）。狀態列用白話提示：還沒拍到全身、看不清膝蓋等。
5. 畫面出現第二人、或人離開畫面太久時，**這一段會自動結束並保存**（該段不會被自動「解鎖」）；只剩一人、回到畫面站好不動，又會自動開始新的一段。
6. 每一段的完整曲線與「下載 CSV／研究 JSON」在下方，可選擇最近 10 段；CSV 欄位與影片分析相同，`inputKind` 為 `camera`。也可按「結束這一段」或「停止」手動結束。
7. 「錄下每一段影片」開啟時（預設），每一段會錄成兩支影片：原始畫面、畫上骨架與膝角度的版本，在下方按「下載影片」存檔。影片只暫存在這個分頁，最近 3 段可下載，關閉網頁就會消失，請先下載。也可以直接在頁面播放（曲線跟著影片走），或按「用完整分析畫面看這一段」（需先停止鏡頭），會切到「上傳影片」頁用這段錄影自動分析，畫面與上傳影片相同。
8. 切換到其他分頁或 App 時，鏡頭會自動關閉並結束該段。
9. 畫面會顯示實測效能（每秒處理次數、鏡頭 fps、延遲中位數與 p95、模型推論時間、掉幀）；研究 JSON 的 `livePerformance` 保存完整數字。每段時間從 0 秒起算。

影像只在本機瀏覽器處理，不上傳；可選擇錄影，影片只暫存在本機分頁記憶體，按下載才會存檔。瀏覽器只允許在 `localhost` 或 https 網址使用鏡頭；
手機用區網 IP（`http://192.168…`）開啟會被擋，需改用 https 部署網址。即時鏡頭與上傳影片共用同一套
人物一致性、關節 QC 與膝角計算；每秒約 10 次是目標值，實際次數視裝置效能而定。

### 實驗性功能（非主要流程）

展開「實驗性功能（ROI／多人／A/B/C 比較）」後，仍可使用原 ROI 編輯、Fixed／Manual Keyframes／Adaptive、
全圖 Multi-Pose（2／3 候選）及同源比較。沒有擴充這些演算法；它們不是本版的穩定性承諾或主要驗收方向。
目前使用實驗設定時，主要區域會明確顯示；收合實驗區不會偷偷改變管線。
按「回到單人主要模式」恢復完整影格單姿態並重新分析，舊結果保留為過期存檔。
收合實驗區會取消未 Apply 的編輯草稿；已完成的分析不因此改變。
歷史方法參考 [架構比較](docs/PIPELINE_COMPARISON.md) 與 [ROI 規約](docs/ROI_TRACKING.md)。

## 使用既有研究 JSON 離線重播 QC

不需影片或模型，也不會再執行 MediaPipe。先在終端機進入專案並完成 `npm ci`，再執行：

```sh
npm run qc:replay -- --input "/Users/你的帳號/Downloads/comparison-你的檔案.json" --output outputs/qc-replay-01
```

把 `--input` 改成自己下載的「研究 JSON」或「A/B/C 比較 JSON」路徑，包含空白時保留引號。
輸出必須是 `outputs/` 下**尚未存在**的新資料夾；下次改成 `qc-replay-02`，避免覆寫。
支援原始 schema 7/8/9；缺少候選、時間或來源座標時會拒絕，不會用單一已選骨架猜測其他人物。

工具會同時計算三種策略：凍結 v0.5.0、分離 QC＋兩次確認、分離 QC＋三次確認。
打開輸出資料夾的 `report.json`，依序查看：

1. `original` 與各 `strategies[].summary`：原始姿態可用數、身分通過數、左右膝有效數及人工鎖定數，分母為 `samples`。
2. `originalWindow06to14`／`window06to14`：0.6–1.4 秒來源時間、腿段長度、身分狀態、關節 QC、恢復計數與原始角度。
3. `failureEpisodes`：已恢復、人工重選終止、或到檔案結束仍未恢復的區間；未恢復不自動解釋成永遠無法恢復。
4. `artificiallyAcceptedSamplesAfterQcChanges`：相較原策略新增自動放行的樣本，逐筆列出時間、側別與人工判讀適用性。
   人工 Wrong/Mixed、Uncertain、僅確認正確人物、未標註分開列出；**新增放行不是 Accuracy 改善**。

派生 session 另存為 `session-1-separated-2.json` 等檔案，保留模型、原始候選、時戳與 parent session。
原始 JSON 不修改，報告記錄輸入 JSON 的 hash；這與影片 hash 是不同的識別資訊。
若重播選到不同候選，不會沿用原候選的人工標籤。原有 Wrong/Mixed/Uncertain 否決仍會阻止最終有效角度。

對 B 的重播固定使用**當時實際裁切區域與候選**，不重跑自動跟隨或搜尋，因此不能直接代表新版重新分析影片的結果。
三份策略報告只是規則對照；要判斷人物與角度是否更正確，仍需原片與人工標註。
輸出含人體特徵，只保存在受限空間，勿提交 Public GitHub。本版沒有增加新的畫面功能。

## 常見問題

| 狀況 | 處理方式 |
| --- | --- |
| N/A 或曲線斷開 | 該取樣無效／確認中；查看原片、另一側與研究診斷，不能當成 0° |
| 分析後一直沒有有效角度 | 檢查模型、拍攝條件與失敗原因；若人物一致性鎖定，重新分析或換合適片段，不強制放行 |
| 模型載入失敗 | 確認網路後按重試；研究者也可在進階設定選取本機檔案 |
| WASM 載入失敗 | 重跑 npm ci 產生本站同版本資源，避免混用 CDN 或其他版本 |
| 設定變更後顯示 stale | 舊結果仍可下載，先重新分析才顯示新曲線／匯出 |
| seek-position-estimate | 瀏覽器沒有精確呈現回呼，只能使用尋時估計；不是已知精確 PTS |
| 影片等待失敗 | 切回分頁、確認編碼並保存診斷；逾時不一定代表不支援編碼 |

## GitHub Pages 部署與驗收

[正式網站](https://chen-jung0929.github.io/115-1-Innovative-Integration-of-Medicine-and-EECS-Final-Project/)由 GitHub Actions 發布。管理者在 **Settings → Pages → Source** 選擇 **GitHub Actions**，並讓 `github-pages` environment 接受 `main`。

- **PR 與部署前檢查**共用 Frontend checks，依序安裝鎖定版本、執行型別檢查、單元測試、Pages 子路徑建置，再以 Chromium 驗證這份 `dist/` 的核心操作。推送至 main 或在 **Deploy to GitHub Pages → Run workflow** 選 main，只有全部通過才會上傳該份產物並發布。檢查失敗時，正式站繼續提供上一版。
- **部署後檢查**會開啟 deploy 回報的 HTTPS 網址，比對首頁的 `meta[name="build-revision"]` 與 Git commit，確認 React 首頁、JS、CSS 與 WASM 資源可用。此步驟失敗時，Actions 會顯示錯誤並保留已部署版本，供管理者決定下一步。
- **排查失敗**時，開啟失敗的 job 日誌，下載該次 run 的診斷 artifact（保留 7 天），用 `npx playwright show-trace <trace.zip>` 檢查操作與網路請求。若部署本身遇到 403，請檢查 Pages 來源、environment 分支限制與工作流程權限。
- **Google 官方服務**可由 **Check official model availability → Run workflow** 獨立驗證。此工作真的下載模型並對合成影片推論；例行部署關卡使用受控回應與合成姿態。

本機重跑需要 FFmpeg、Node（見 `.nvmrc`）與 Playwright Chromium：

```sh
npm ci
npx playwright install chromium
export PAGES_BASE_PATH=/115-1-Innovative-Integration-of-Medicine-and-EECS-Final-Project/
npm run check
npm run test:smoke
```

`npm run test:official` 可單獨測試真實模型；`npm run preview` 可開啟相同建置。跨瀏覽器指令、實測時間與人工驗收步驟見[第 23 輪驗證紀錄](docs/updates/iteration-23.md)。
