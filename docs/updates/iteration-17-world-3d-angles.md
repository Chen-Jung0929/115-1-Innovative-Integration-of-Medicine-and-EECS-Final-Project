# Iteration 17：3D 骨架角度試驗（2026-11-22）

> 分支 `feature/world-3d-angles`（base：`feature/ui-redesign`）。試驗功能，2D 影像角度仍是主要量測與匯出值。

## 為什麼

使用者回饋：正面或斜角拍攝時，膝、髖角度常常「不太準」，例如深蹲蹲很低時左膝只顯示 21°、右膝 76°。原因是目前的角度都在 **2D 影像平面** 上算：正面拍時大腿朝向鏡頭，在畫面上被壓短，彎曲角就被低估；身體稍微轉一點，左右兩邊就差很多。

MediaPipe 除了 2D 點，也會輸出一組 **3D 骨架點（world landmarks，公尺、以髖為中心）**，之前沒有用到。

## 改了什麼

- `src/pose/mediapipe.ts`：每個點多存一個選填的 `world: [x, y, z]`（`Landmark.world`）。舊的分析檔沒有這個欄位，畫面會顯示 N/A，請重新分析。
- `src/biomechanics/world.ts`：`worldFlexion()` 用 3D 點算膝（髖–膝–踝）與髖（肩–髖–膝）的彎曲角 = 180° − 3D 夾角（`world-landmark-3d-flexion-v1`，自訂）。
- 畫面：膝、髖彎曲的大數字下面多一行小字「3D 骨架 X°」，只有該格 2D 角度通過 QC 時才顯示；「怎麼算？」裡有說明。
- 曲線：「曲線指標」多兩個選項「膝彎曲（3D 骨架，試驗）」「髖彎曲（3D 骨架，試驗）」。
- CSV、門檻、提示規則都沒有改；3D 點會跟著 landmarks 存在研究用 JSON 裡。

## 3D 骨架視窗（同日，使用者要求）

3D 骨架視窗預設改成真實骨頭外形（OpenSim 骨頭模型，取自 opencap-viewer，Apache-2.0，放在 `public/bones/`），左側淡藍、右側淡橘，依 3D 點擺位與縮放；右上可切「骨頭／線條」（ADR-070）。新增套件 `three@0.187.0`，第一次拉下這個分支要先跑 `npm install`。這只是外觀，不是 OpenSim 運動學計算。

## 初步比對（不是正式驗證）

參考答案：OpenCap 官方測試資料（`stanfordnmbl/opencap-test-data`）
- LabValidation subject2 `squats1`：5 支同步 iPhone，拍攝角度約 0°（正面）、35°、45°、65°、75°（接近側面），參考值為 5 鏡頭 OpenCap 的 OpenSim 運動學。
- `sync_2-cameras/squats`：2 支近正面 iPhone，參考值為雙鏡頭 OpenCap 輸出。

方法：MediaPipe Pose（Python，Lite 與 Full 模型，每秒 10 格）算 2D 與 3D 彎曲角，以膝角互相關對齊時間，比較「深蹲最低點」（參考值前 15%）的平均絕對誤差。髖的參考值用 hip_flexion − lumbar_extension（軀幹對大腿），定義仍不完全相同。腳本與結果：專案檔案 `research/world-3d-check/`（不放進 repo，避免放入影片與點位）。

## 解讀與限制

1. **3D 骨架大幅降低對拍攝角度的依賴**：2D 只有接近正側面時準（最低點誤差 2–82°），3D 在每個角度都在約 3–19°。
2. **3D 站直時會顯示彎曲 8–29°**（模型的 3D 膝蓋幾乎不會完全打直），所以 3D 數字的變化範圍比實際小；先不做校正（用站直值扣除反而讓最低點變差）。
3. **3D 仍有 5–20° 誤差**，不能取代 OpenCap 雙鏡頭或動作捕捉；門檻不能直接用這個數字定。
4. 只有 2 位受試者、正確動作、實驗室光線。下一步：用研究組的資料（多鏡頭＋錯誤動作）重做，再決定主要數字要不要改用 3D 或「側面用 2D、其他用 3D」。
