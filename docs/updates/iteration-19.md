# 第 19 輪：影片與鏡頭自動準備姿態辨識

在影片頁按「開始分析」或在即時頁按「開啟鏡頭」，即可取得 Google 官方 Lite 模型（float16/1）。兩個入口都顯示準備狀態，下載失敗時可直接重試。進階設定仍可選用本機檔案。這項更新從 main 的 e00fda2 開發。

同一頁重用模型內容、已算出的 SHA-256 與 WASM 檔案設定。執行中的鏡頭沿用同一個辨識實例；切換到獨立影片或新的鏡頭串流時，依各自的時間戳與追蹤狀態初始化新實例。CSV 與研究 JSON 的量測及來源欄位沿用原格式。

## 實際驗證

| 檢查 | 結果 |
| --- | --- |
| `npm ci`、`npm run typecheck`、`npm test` | 安裝成功；型別檢查通過；41 個測試檔、286 個測試通過。 |
| `PAGES_BASE_PATH=/115-1-Innovative-Integration-of-Medicine-and-EECS-Final-Project/ npm run build` | 建置成功，469 個模組；仍有既有的 bundle 大小提示。 |
| `npm run test:browser`（Chrome） | 34 個通過，2 個略過。涵蓋按需下載與重試、合成姿態的骨架、角度、曲線及匯出，以及模擬鏡頭的啟停。兩個指定真人影片的測試需團隊提供測試素材。 |
| 本機正式子路徑、全新 Chrome 環境、實際 Google 下載 | 分別以合成 MP4 及模擬鏡頭作第一個輸入，首次分析前沒有官方下載。兩種啟動順序均成功，切換輸入後共計只請求一次官方模型。子路徑 WASM 回應 200。合成影片完成 10 筆取樣並匯出研究 JSON。 |
| 斷線恢復 | 攔截第一次官方下載，再解除攔截。影片按「重試分析」、鏡頭按「重試開啟鏡頭」，均成功載入真正的模型，後續切換輸入沿用同一份模型內容。 |

研究 JSON 的實測模型 SHA-256 為 `59929e1d1ee95287735ddd833b19cf4ac46d29bc7afddbbf6753c459690d574a`。網路檢查發現 MediaPipe 1.2.3 另外嘗試連線至 Google 的 SDK 紀錄端點。本版以頁面 connect-src 阻擋該連線，已在兩種啟動順序觀察到瀏覽器阻擋事件，兩者均可繼續推論。
