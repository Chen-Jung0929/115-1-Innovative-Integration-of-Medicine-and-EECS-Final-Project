# 第 22 輪：即時鏡頭錄影（只存在裝置上）

使用者確認團隊的訴求是「不上傳」，錄影本身可以，並選擇原始畫面與含骨架的版本都錄（ADR-091）。

## 改動

- 新增 `src/input/recorder.ts`：挑選瀏覽器支援的錄影格式（MP4 優先、否則 WebM）、錄影與下載。
- `src/app/LivePanel.tsx`：每段開始量測時同時錄原始鏡頭串流，以及一張合成畫布（鏡頭畫面 + 骨架疊圖 + 左右膝彎曲角與秒數）；段落結束時停止錄影，在「已保存的量測段」顯示兩個下載按鈕。新增開關「錄下每一段影片」（預設開），說明文字改為「不會上傳，影片暫存在這台裝置」。
- 已保存段落可直接播放錄影（含骨架／原始畫面切換），曲線游標與 3D 骨架跟著影片時間；「用完整分析畫面看這一段」把原始錄影交給上傳影片頁並自動分析，畫面與上傳影片相同（ADR-092）。切到上傳影片頁再回來時，已保存的段落與影片仍在（以前切換頁面會清空）；量測中途切走，該段也會先保存。
- 經獨立 agent 審核兩輪：第 1 輪沒過（切到上傳影片頁會清掉已保存段落），修正後第 2 輪通過，並依其建議補上「中途切走也保存」與錄影完成後重新顯示。
- e2e：即時鏡頭測試在停止後下載兩支影片、在頁面播放、切換原始畫面，並送到完整分析直到「分析完成」。

## 檢查與限制

- `npm run typecheck`、`npm test`（291 個）、`npm run build`、`npm run test:browser`（36 通過、2 個既有條件略過）通過。用模擬鏡頭抽出含骨架影片的最後一格，確認骨架與角度文字有畫上。
- 碼率原始 1.2 Mbps、含骨架 1 Mbps，只保留最近 3 段影片（ADR-091），單段 10 分鐘上限時最多約 500 MB 記憶體；平板與手機（尤其 iPad Safari 上同時錄兩支影片＋姿態辨識的效能）尚未實測。
- 含骨架影片的骨架每秒更新約 10 次，動作快時會略落後身體。
- 經獨立 agent 審核一輪後修正：README 補錄影說明、降低碼率與保留段數、錄影錯誤時保留已錄部分。切到其他分頁時鏡頭會關閉，錄影也一起結束並保存。
